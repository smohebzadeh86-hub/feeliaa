## ۱. هدف

الان تنها نقشِ سیستم «تراپیست» است — هرکی ثبت‌نام کنه، بلافاصله یه حساب کامل با دسترسی به مراجعینِ خودش داره. هیچ‌جا کسی نمی‌تونه ببینه چند نفر ثبت‌نام کردن، کی فعاله، کدوم حساب باید غیرفعال بشه، یا کل سیستم چقدر داره استفاده می‌شه.

پنل ادمین این نقشِ دومِ سیستم رو اضافه می‌کنه: یک حساب با دیدِ کامل روی همه‌چیز — ثبت‌نامی‌ها، فعال/غیرفعال‌کردنِ حساب‌ها، و دسترسیِ درسته (نه بی‌قاعده) به دیتای هر تراپیست.

## ۲. مدلِ نقش — چرا یک سیستمِ جدا نه

ادمین یک جدولِ جدا/لاگینِ جدا نداره. ادمین **همون حسابِ تراپیستیه با یک فلگِ اضافه** (`is_admin`). دلیل: پیچیدگیِ یک سیستمِ authِ دومِ کامل (کوکیِ جدا، فرمِ ورودِ جدا) برای این مقیاس توجیه نداره؛ یک ستون کافیه.

**بوت‌استرپِ اولین ادمین:** یک env var به اسم `ADMIN_PHONE` — هر بار کسی با اون شماره لاگین می‌کنه، سرور خودکار `is_admin=true` رو روش ست می‌کنه. یعنی صاحبِ سرور با گذاشتنِ شماره‌ی خودش توی `.env`، بدونِ نیاز به SQL دستی، ادمین می‌شه.

## ۳. مدلِ دیتا (تغییرات)

```sql
ALTER TABLE therapists ADD COLUMN is_admin BOOLEAN NOT NULL DEFAULT false;
ALTER TABLE therapists ADD COLUMN active     BOOLEAN NOT NULL DEFAULT true;
```

- `active=false` یعنی حساب غیرفعاله — لاگین رد می‌شه (پیام صریح: «این حساب غیرفعال شده»)، ولی دیتاش پاک نمی‌شه (قابلِ فعال‌سازیِ دوباره).
- `is_admin` جدا از `active` است — می‌شه یک ادمین رو غیرفعال کرد (خودِ ادمینِ اصلی نمی‌تونه خودش رو غیرفعال کنه، جلوگیری از قفل‌شدنِ کامل).

## ۴. فیچرها (این نسخه)

| # | فیچر | توضیح |
|---|---|---|
| F1 | داشبورد آمار | تعداد کل تراپیست‌ها، مراجعین، جلسات، جلساتِ امروز/این هفته |
| F2 | فهرستِ تراپیست‌ها | جست‌وجو (نام/شماره)، مرتب‌سازی، هرکدوم با تعدادِ مراجع/جلسه و آخرین فعالیت |
| F3 | فعال/غیرفعال‌کردنِ حساب | یک toggle روی هر ردیف — فوری اثر می‌کنه (نشستِ فعلیِ اون حساب هم باطل می‌شه) |
| F4 | تبدیل به ادمین / گرفتنِ نقشِ ادمین | فقط ادمین می‌تونه ادمینِ دیگه بسازه؛ خودش رو نمی‌تونه پایین بیاره اگه تنها ادمین باشه |
| F5 | جزئیاتِ یک تراپیست | باز کردنِ یک تراپیست → فهرستِ مراجعینش (کد، نام مستعار، تعداد جلسه) — **بدونِ نمایشِ متنِ رونویسی‌شده** (حریمِ خصوصیِ مراجع، حتی از دیدِ ادمین) |
| F6 | حذفِ کاملِ یک تراپیست | با تأییدِ صریح (تایپِ شماره) — آبشاری: همه‌ی مراجعین/جلسات/یادداشت‌هاش هم حذف می‌شن |
| F7 | حذفِ یک مراجعِ خاص (از دیدِ ادمین) | برای موردهای نقضِ قانون/درخواستِ حذفِ داده |

### عمداً خارج از این نسخه

- **نمایشِ متنِ رونویسی‌شده‌ی جلسات به ادمین** — این حریمِ خصوصیِ درمانیِ مراجعه، حتی مالکِ سیستم نباید بدونِ دلیلِ مشخص (شکایت/درخواستِ قانونی) بتونه بخونتش. اگه لازم شد، باید یک مسیرِ جداگانه با لاگ/دلیل باشه، نه یک دکمه‌ی معمولی توی پنل.
- ویرایشِ مستقیمِ دیتای تراپیست (رمز عبورِ کسی رو عوض کردن و امثالش) — ریسکِ امنیتی، بمونه برای بعد اگه واقعاً لازم شد.
- گزارش‌گیریِ پیشرفته/نمودار — فقط اعدادِ خامِ داشبورد کافیه برای این مرحله.

## ۵. مدلِ دسترسی

```
GET/POST/PATCH/DELETE  /api/admin/*   → فقط is_admin=true (وگرنه ۴۰۳، نه ۴۰۴ — چون ادمین باید بدونه چرا رد شد)
```

هیچ مسیرِ ادمین چیزی از دیتای تراپیستِ عادی رو عوض نمی‌کنه مگر با endpointِ صریحِ ادمین — یعنی routeهای معمولیِ `/api/clients`, `/api/sessions` دست‌نخورده می‌مونن، فقط یک لایه‌ی موازیِ `/api/admin/*` اضافه می‌شه.

## ۶. API

```
GET    /api/admin/stats
       → { therapists, clients, sessions, sessions_today, sessions_this_week }

GET    /api/admin/therapists?q=search
       → [{ id, phone, email, name, is_admin, active, created_at,
            client_count, session_count, last_session_at }]

PATCH  /api/admin/therapists/:id
       body: { active?: boolean, is_admin?: boolean }
       → قوانین: نمی‌تونی خودت رو غیرفعال کنی؛ اگه تنها ادمینی، نمی‌تونی is_admin خودت رو false کنی

DELETE /api/admin/therapists/:id
       → آبشاری؛ نمی‌تونی خودت رو حذف کنی

GET    /api/admin/therapists/:id/clients
       → [{ id, code, alias, session_count, created_at }]  (بدونِ transcript)

DELETE /api/admin/clients/:id
       → حذفِ یک مراجعِ خاص، مستقل از اینکه مالِ کدوم تراپیسته
```

## ۷. UI — بر اساسِ سیستمِ طراحیِ فیلیا

بدونِ هیچ توکنِ رنگ/فونتِ تازه — دقیقاً همون زبانِ بصریِ فعلی:

- **صفحه‌ی جدید** `screenAdmin` — همون الگوی کارت/هدر/بنر که همه‌جای اپ هست.
- **آمار**: چهار تا کارتِ کوچیکِ عدد (grid، مثلِ الگوی موجودِ کارت‌ها) بالای صفحه.
- **جست‌وجو**: همون `.search-box` که توی لیستِ مراجعین هست.
- **فهرستِ تراپیست‌ها**: کارت‌های شبیهِ `.client-card` — نام/شماره، badge برای «ادمین» (رنگِ gold، هم‌خانواده‌ی `.status-pill`)، toggle برای فعال/غیرفعال (سوییچِ همونی که توی `.toggle-row` هست).
- **تأییدِ حذف**: همون مودالِ تایپ‌کدِ الگوی حذفِ مراجع.
- **دسترسی به صفحه**: یک آیکون‌باتنِ جدید توی هدر، فقط وقتی `currentTherapist.is_admin===true` نشون داده می‌شه.

## ۸. معیارِ پذیرش

- حسابِ غیرادمین، `/api/admin/*` رو صدا بزنه → ۴۰۳.
- شماره‌ی داخلِ `ADMIN_PHONE` لاگین کنه → `is_admin=true` می‌شه، آیکونِ پنل ظاهر می‌شه.
- ادمین یک تراپیست رو غیرفعال کنه → نشستِ فعلیِ اون تراپیست بلافاصله باطل می‌شه (درخواستِ بعدیش ۴۰۱ می‌گیره).
- ادمین سعی کنه خودش رو غیرفعال/حذف کنه (وقتی تنها ادمینه) → رد می‌شه با پیامِ روشن.
- توی جزئیاتِ یک تراپیست، هیچ‌جا متنِ رونویسی‌شده دیده نمی‌شه.
