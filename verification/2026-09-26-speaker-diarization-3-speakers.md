# 2026-09-26 — تفکیکِ سه گوینده (زوج‌درمانی): آزمایشِ کنترل‌شده‌ی کلِ مسیر

> Evidence (مشاهده در یک زمان). ماشینِ dev، کلیدِ Sonioxِ مشترک، بدونِ دادهٔ مراجع.

## سؤال
مالک: «در تستِ ۳نفره فقط ۲ گوینده می‌آید؛ قبلاً درست جدا می‌کرد؛ پس مشکل از کد است؟»

## داده‌ها
- **صدایِ تستِ مالک:** جلسه‌ی dev `ec144271…` — ۷ سگمنتِ آرشیو (۹۰ث، opus، 48kHz، ۲کاناله). سطح: RMS −30dB، peak −2dB،
  noise floor −47dB (سالم). ضبط با NS/AGC/EC **خاموش** (تغییرِ موقتِ همان روز).
- **صدایِ کنترل (ground truth معلوم):** مکالمه‌ی زوج‌درمانیِ ساختگیِ ۲۰ نوبتی (۱۲۷ث) با TTSِ Soniox (`tts-rt-v2`، فارسی):
  درمانگر=Adrian (مرد)، زن=Maya، شوهر=Daniel (مرد) — عمداً دو صدایِ مردانه.
- ابزارها (scratchpadِ نشست، خارج از repo): `diar-ab.mts` (همان فایل → realtime با کانفیگِ دقیقِ `feelia-rt.js` ±context
  ±endpoint، و async `stt-async-v5` ±context)، `mkconv.mts`، `capture-server.mjs` (Chromeِ واقعیِ headless با
  `--use-file-for-fake-audio-capture` + همان دو MediaRecorderِ `feelia-rt.js`: live پیش‌فرض/250ms و durable 24kbps/1000ms).

## نتیجه‌گیری
1. کانفیگِ Sonioxِ کد (مدل، diarization، endpoint، context) و کلِ مسیرِ ضبطِ مرورگر (getUserMedia → MediaRecorder →
   WS/آرشیو → async) با صداهایِ متمایز **۳ گوینده را درست جدا می‌کنند**. سقف یا باگی در کد که گوینده‌ها را ادغام کند نیست.
2. رویِ صدایِ تستِ مالک حتی بهترین مدل (async) با راهنماییِ صریحِ «۳ نفر» فقط ۲ خوشه می‌سازد ⇒ اطلاعاتِ تمایزِ صدایِ نفرِ
   سوم در خودِ ضبط وجود ندارد/کافی نیست (صدایِ مشابه با یکی دیگر، سهمِ گفتاریِ کم، هم‌پوشانی، فاصله از میکروفون).
3. NS/AGC/EC در آزمایشِ کنترل اثری نداشت؛ چون تستِ میدانیِ مالک بعد از خاموش‌کردن بدتر گزارش شد، به حالتِ قبلی (روشن) برگشت.
4. باگِ واقعیِ پیدا‌شده: شماره‌گذاریِ متنِ زنده از ۰ (از `2763414`) — رفع شد (از ۱).

## پیگیری: هشدارِ کیفیتِ ضبط (تصمیمِ مالک: فقط همین گزینه)
کالیبراسیونِ `createAudioQualityMonitor` (فریم ۵۱۲تایی هر ~۱۶.۷ms، پنجره ۳۰ث):

| ورودی | نتیجه‌ی پنجره‌ها |
|---|---|
| صدایِ واقعیِ مالک (۱۲۰ث) | همه ok (p10≈−51، p95 −21..−28) |
| Chrome، DSP روشن / خاموش | همه ok (clip ≤۰.۶٪) |
| صدایِ مالک −15dB | همه ok (p95 −36..−43) |
| صدایِ مالک −25dB (دور) | ok ← too_quiet ← … |
| صدایِ مالک +22dB | clipping از پنجره‌ی اول |
| بی‌صدا (صفر) | ok ← no_signal ← … |
| صدایِ مالک + نویزِ صورتیِ بلند | ok ← noisy ← … |

مرورگر (پنلِ داخلی، `localhost:3000`): اسیلاتورِ ۰.۰۰۲ → آنالایزرِ واقعیِ `attachLevelMeterToStream` → پس از دو پنجره متنِ
«صدا ضعیف ضبط می‌شود…» در `#audioQualityHint` نمایان شد؛ `stopLevelMeter` آن را پنهان کرد؛ کنسول بدونِ خطا. (پنل پنهان بود و rAF
متوقف؛ فریم‌ها با زمانِ شبیه‌سازی‌شده از همان آنالایزر خورانده شدند.) ارسالِ `rt.audio_quality_warn` به `obs_events` end-to-end تست نشد.
