# Verification — چرخشِ کاملِ لاگِ JSONLِ لایه‌ی رصد (`OBS_LOG_MAX_BYTES`)

**تاریخ:** 2026-09-23
**هدف:** بستنِ آخرین آیتمِ بازِ checklistِ پلنِ observability (بخش ۶، آیتمِ ۷) — تستِ واقعیِ
چندچرخشیِ rotation که در verificationِ قبلی (`2026-09-23-obs-phase1-2-remaining-checklist-completion.md`)
به‌دلیلِ hardcode بودنِ `MAX_BYTES` و بودجه‌ی زمانی SKIPPED مانده بود.
**این پاس کدی تغییر نداد** — فقط verification.

## روش

با مجوزِ صریحِ مالک: سرورِ dev رویِ پورتِ ۳۰۰۰ (که به نشستِ/کاربرِ دیگری تعلق داشت) توسطِ خودِ
مالک در ترمینالِ خودش متوقف و با `set OBS_LOG_MAX_BYTES=64000 && pnpm dev` (سقفِ فایل ~۶۴KB
به‌جایِ ۸MBِ پیش‌فرض) دوباره بالا آورده شد — چون این عمل (kill کردنِ پروسه‌ی این نشست) توسطِ
classifierِ auto-modeِ محیط (`Interfere With Workloads`) رد می‌شد.

سپس یک حسابِ QA canaryِ تازه ثبت‌نام شد (`qa-obs-rotate-1790113870@example.test`،
`id=3e95c98d-2d74-4b14-a530-b726fae3c0dc`) و ترافیکِ واقعیِ HTTP تولید شد:
- ابتدا batchهایِ `POST /api/obs/events` (کشفِ جانبی: رویدادهایِ UI فقط به DB می‌روند، نه
  فایل — `logUiEvents` هرگز `writeJsonl` صدا نمی‌زند، فقط `logEvent` این کار را می‌کند؛
  `httpHook.ts` خودِ رویدادِ `http.request` را همیشه در فایل می‌نویسد).
- برایِ رشدِ سریع‌ترِ فایل، ~۳۴۰۰ درخواستِ `GET /api/health` (بدونِ auth، بدونِ rate-limit)
  در یک حلقه زده شد — هر درخواست یک خطِ `http.request` در JSONL می‌نویسد.

## نتیجه — PASS

اندازه‌ی واقعیِ فایل‌ها بعدِ ترافیک:
```
 48165  obs.jsonl
 64220  obs.jsonl.1
 64222  obs.jsonl.2
 64222  obs.jsonl.3
 64220  obs.jsonl.4
 64220  obs.jsonl.5
```
- هر فایلِ چرخش‌یافته دقیقاً نزدیکِ سقفِ `OBS_LOG_MAX_BYTES=64000` است (تأییدِ خواندنِ صحیحِ
  env var — قبلِ فیکسِ پاسِ قبلی این مقدار کاملاً hardcode بود).
- `obs.jsonl.1` تا `.5` هر پنج‌تا حاضرند (`KEEP=5`).
- بعدِ یک دورِ اضافیِ ۴۰۰ درخواستِ دیگر، md5ِ `obs.jsonl.5` عوض شد (از `301006...` به
  `c68e2d...`) — یعنی کاسکیدِ rotation واقعاً درحالِ حرکت است (فایلِ قدیمی‌تر عقب می‌رود).
- **`obs.jsonl.6` هرگز ایجاد نشد** (`test -f ... && echo BUG || echo "no .6 file - correct"`
  → `no .6 file - correct`) — یعنی سقفِ سختِ دیسک (`MAX_BYTES × (KEEP+1)` ≈ ۳۸۴KB در این
  تستِ کوچک‌شده، معادلِ ۴۸MB در حالتِ پیش‌فرضِ production) واقعاً برقرار است؛ قدیمی‌ترین فایل
  حذف می‌شود، نه اینکه به `.6` منتقل شود.

## وضعیت

هیچ کدِ اپلیکیشن در این پاس تغییر نکرد. `cd server && npx tsc --noEmit` اجرا نشد چون هیچ
فایلِ TSای تغییر نکرد. سرورِ dev (متعلق به مالک) با `OBS_LOG_MAX_BYTES=64000` هنوز درحالِ
اجراست — طبقِ تصمیمِ مالک برایِ توقفِ فعلیِ کار، بازگردانی به مقدارِ پیش‌فرض (حذفِ env var و
ری‌استارت) به مالک واگذار شد. حسابِ QA canaryِ این پاس (`3e95c98d-...`) طبقِ رویه‌ی همیشگی
حذف نشد (LAW-006 — عملیاتِ مخرب نیازمندِ مجوزِ صریح).
